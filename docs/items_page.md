# 全部物品与信息调整 · 0.5.5

底部导航新增“物品”，与首页、历史并列。读取所有已存 Item，按最近调整时间排列，包含没有库存的物品；不会被旧的“最近 20 件”接口截断。每条显示名称、位置、库存数量，点击打开首页查询和历史共用的信息卡。卡片默认完整展开，内容可滚动，避免 OPPO 大字体下半展开状态遮住底部操作。

信息卡提供：

- **调整信息**：修改名称、位置、库存及各份到期日期。填写本次新增数量（0–100 份），下方会出现新增库存的日期按钮。现有库存逐份提供日期选择和“删除这一份”；删除二次确认后标为待删除，可撤销。页面显示调整后库存，点击“保存调整”统一生效，取消/返回不写库。日期使用已有日期选择页，支持清空。零库存物品也能在这里新增并设置日期。
- **增加库存**：打开可编辑库存草稿，填写本次新增数量并逐份选择到期日期，确认后添加。无需先说话或等待 NLU 解析。
- **调整日期**：某份库存的快捷入口，进入调整页并直接打开该份的日期选择页。
- **删除**：只删除点选的这一份库存，必须二次确认。信息卡保持打开、数量原地刷新；删至零时仍保留 Item 和位置。没有新增批量删除或整个 Item 删除操作。

名称调整与自然语言草稿的“名称纠正”分开实现。`ItemEditDraft` 保存原 Item 快照、编辑值、新增库存和逐份确认过的删除 ID；`RoomInventoryRepository.updateItem` 在同一事务里验证原快照、检查重名、更新原 Item 和选中的到期日期、删除确认的实例并添加新实例。保留 Item 和保留的 InventoryUnit ID、创建时间、未编辑的库存字段，避免把改名当作创建另一物品。重复名称或过期快照会阻止全部写入，不合并记录；重复保存同一草稿也不能重复加库存。新增数量的减少只移除尚未保存的新草稿，不能自动删掉现有库存。

列表通过 `observeAll()` 监听 Room 的物品与库存数据变化；信息卡、列表数量与名称随成功修改刷新。历史按 Item ID 打开当前信息，改名后旧历史仍指向原物品。

数据库仍为 schema v2，未修改表结构。ASR/NLU 权重、提示词 v5、语音交互保持原样。这次仅在 OPPO Find X8s 验证，更新使用 `install -r`，保留正式物品和历史。

## 验证范围

使用隔离数据库验证 25 件全部可达、空态、零库存保留、改名不改 ID、名称冲突拒绝、非法日期拒绝、过期编辑拒绝、取消不写入、不同库存日期独立保存、手动添加、逐份删除二次确认，以及历史打开改名后的当前信息。手动物品管理路径的 NLU 调用计数应为 0。

0.5.5 补充：从零库存新增并设置不同日期、非法数量阻止保存、新增数量变化保留已有日期、删除确认取消/撤销、整页取消丢弃新增和删除、数量和日期一并保存、清空日期、重复/过期草稿拒绝、删至零后再次添加。详见 [0.5.5 验证](../../physical-memory-oppo-validation/item-edit-stock/README.md)。
